Dưới đây là thiết kế chi tiết toàn bộ quy trình kỹ thuật cho 5 bước của Phase 3. Mỗi bước được cấu trúc như một đặc tả tài liệu kỹ thuật hoàn chỉnh (tương ứng với các file `003_01` đến `003_05`), bao gồm cơ sở tài liệu gốc từ Windows SDK, phân tích kiến trúc, thứ tự thực thi và các điểm kiểm tra validation.

### Bước 1 (`003_03_TaskbarButton_COM.md`): Triển khai hạ tầng `ITfLangBarItemButton` và kết nối Taskbar

**1. Cơ sở chuẩn hóa từ Windows SDK**

- Tra cứu trực tiếp từ file IDL gốc: `C:\Program Files (x86)\Windows Kits\10\Include\<version>\um\ctfutb.idl`.  
- **GUID chuẩn:**
  - `ITfLangBarItem`: `73830352-D722-4179-A501-AEBC6BE65053`
  - `ITfLangBarItemButton`: `28888638-0187-42EB-BFF5-B92AC1AC7668`
  - `ITfLangBarItemMgr`: `BA468C55-9956-4FB1-A59D-52A7DD7CCB23`
  - `ITfLangBarItemSink`: `57D42764-50AC-4310-B624-CC17112183DF`
  - `GUID_Item_BambooMintKey`: Khởi tạo một GUID tĩnh mới đại diện duy nhất cho nút icon của ứng dụng trên thanh ngôn ngữ.

**2. Phân tích kiến trúc VTable**

- `ITfLangBarItemButton` kế thừa phân cấp: `IUnknown` -> `ITfLangBarItem` -> `ITfLangBarItemButton`.
- Thứ tự con trỏ hàm trong VTable bộ nhớ:
  1. `QueryInterface`, `AddRef`, `Release` (IUnknown).
  2. `GetInfo`, `GetStatus`, `Show`, `GetTooltip` (ITfLangBarItem).
  3. `OnClick`, `InitMenu`, `OnMenuSelect`, `GetIcon`, `GetText` (ITfLangBarItemButton).
- Kiểu struct thông tin `TF_LANGBARITEMINFO`:
  - Cần cấu hình cờ `dwStyle = TF_LBI_STYLE_BTN_BUTTON | TF_LBI_STYLE_SHOWNINSTATUS` (cho phép hiển thị trực tiếp ở khay hệ thống/Taskbar).
  - Chuỗi mô tả `szDescription` (32 ký tự UTF-16) đặt tên là `"BambooMintKey Mode"`.

**3. Quy trình thực thi**

- **Giai đoạn khởi tạo:** Cấp phát bộ nhớ không thu gom (native memory) cho VTable của `LangBarItemButton` trong C# NativeBridge.
- **Giai đoạn vòng đời Service (`ActivateEx`):**
  1. `ITfThreadMgr` nhận được từ Windows khi kích hoạt bộ gõ.  
  2. Gọi `QueryInterface` trên `ITfThreadMgr` để lấy con trỏ tới `ITfLangBarItemMgr`.
  3. Gọi `pLangBarItemMgr->AddItem(pMyLangBarItem)` để đưa icon lên Taskbar.
  4. Lấy con trỏ `ITfSource` từ nút vừa thêm để gọi `AdviseSink` với `ITfLangBarItemSink` (dùng để nhận thông báo khi Windows yêu cầu làm mới).
- **Giai đoạn kết thúc (`Deactivate`):**
  1. Gọi `UnadviseSink` hủy đăng ký lắng nghe sự kiện.
  2. Gọi `pLangBarItemMgr->RemoveItem(pMyLangBarItem)` để xóa sạch icon khi chuyển sang bộ gõ khác hoặc tắt ứng dụng.

**4. Checkpoint kiểm thử:**

- Dùng lệnh PowerShell tạo harness kiểm tra xem `QueryInterface` tới `IID_ITfLangBarItemButton` có trả về `S_OK` hay không.  
- Chạy `test-register.ps1`, chọn bộ gõ, kiểm tra xem Windows Explorer/Taskbar có gọi hàm `GetInfo` và `GetStatus` không.  

### Bước 2 (`003_02_IconHelper_DynamicRendering.md`): Cơ chế vẽ Icon động (V/E) và cập nhật hiển thị

**1. Vấn đề kỹ thuật cần xử lý**

- Nếu trỏ `IconFile` tới đường dẫn file `.ico` cứng trên ổ cứng, hệ thống rất dễ gặp lỗi không tải được icon khi chạy trong sandbox (UWP/AppContainer), hoặc gặp lỗi đường dẫn tương đối.  
- Windows TSF yêu cầu phương thức `GetIcon(HICON* phIcon)` trả về một handle icon (`HICON`) hợp lệ trong bộ nhớ mỗi khi cần vẽ lại Taskbar.

**2. Phân tích luồng tạo HICON động qua Win32 GDI**

- Khởi tạo Memory Device Context (`CreateCompatibleDC`) tương thích với màn hình hiện tại.
- Tạo 32-bit DIB/Bitmap kích thước chuẩn khay hệ thống (16x16 pixel hoặc tương thích DPI qua `GetSystemMetrics(SM_CXSMICON)`).
- Tô nền trong suốt (Transparency/Mask).
- Dùng API Win32 `DrawTextW` để render trực tiếp:
  - Ký tự **"V"** nền trong suốt, màu đỏ cờ (`RGB(220, 20, 60)`).
  - Ký tự **"E"** nền trong suốt, màu xanh dương đậm (`RGB(30, 144, 255)`).
- Gọi `CreateIconIndirect` ghép Bitmap màu và Bitmap mặt nạ thành con trỏ `HICON`.
- Giải phóng sạch các đối tượng GDI trung gian (`DeleteObject`, `DeleteDC`, `ReleaseDC`) để triệt tiêu nguy cơ rò rỉ bộ nhớ (GDI leak).

**3. Quy trình xử lý Toggle trạng thái**

- Bắt sự kiện người dùng tương tác:
  - **Chuột:** Windows gọi hàm `OnClick(uint click, POINT pt, RECT* prcArea)` trên `ITfLangBarItemButton`. Kiểm tra nếu `click == 2` (`TF_LBI_CLK_LEFT` - chuột trái), tiến hành đảo trạng thái.
  - **Bàn phím:** Bắt tổ hợp phím tắt toggle (`Ctrl + Shift` hoặc `Alt + Z`) trong `ITfKeyEventSink::OnKeyDown`.
- Cập nhật trạng thái logic: Đảo biến `IsVietnameseMode` trong `BridgeStateManager`.
- Bắn tín hiệu làm mới giao diện:
  - Gọi `pLangBarItemSink->OnUpdate(TF_LBI_ICON | TF_LBI_TOOLTIP)`.
  - Windows Taskbar tự động gọi lại hàm `GetIcon` để lấy handle `HICON` mới và vẽ lại ngay lập tức.

**4. Checkpoint kiểm thử:**

- Dùng phần mềm *GDIView* để theo dõi handle GDI: số lượng Bitmap/DC không được tăng dần theo thời gian khi liên tục click toggle V/E.
- Đổi chế độ bằng chuột trái, icon Taskbar phải chuyển đổi mượt mà giữa chữ V và E.

### Bước 3 (`003_03_TaskbarContextMenu.md`): Menu ngữ cảnh chuột phải trên Taskbar

**1. Cơ sở chuẩn hóa từ Windows SDK**

- File định nghĩa: `ctfutb.idl` và `ctfutb.h`.
- Hằng số ID menu hệ thống:
  - `TF_LBMENUID_APP`: Giá trị base `0x00010000`. Toàn bộ ID của các mục tùy chỉnh do ứng dụng thêm vào phải bắt đầu từ giá trị này trở đi.
- Interface tương tác menu của Windows TSF: `ITfMenu`.

**2. Cấu trúc menu phân cấp**

- Menu cấp 1:
  - `[x] Gõ tiếng Việt (Ctrl + Shift)` (ID: `APP_CMD_TOGGLE_MODE`)
  - `---` (Separator)
  - `Kiểu gõ` (Submenu / Popup):
    - `(*) Telex` (ID: `APP_CMD_INPUT_TELEX`)
    - `( ) VNI` (ID: `APP_CMD_INPUT_VNI`)
    - `( ) Simple Telex` (ID: `APP_CMD_INPUT_SIMPLETELEX`)
  - `Bảng mã` (Submenu / Popup):
    - `(*) Unicode dựng sẵn` (ID: `APP_CMD_CHARSET_UNICODE`)
    - `( ) Unicode tổ hợp` (ID: `APP_CMD_CHARSET_COMPOUND`)
    - `( ) TCVN3 (ABC)` (ID: `APP_CMD_CHARSET_TCVN3`)
  - `---` (Separator)
  - `Tùy chọn cấu hình...` (ID: `APP_CMD_OPEN_SETTINGS`)

**3. Quy trình thực thi**

- **Hàm `InitMenu(ITfMenu\* pMenu)`:**
  1. Nhận con trỏ `ITfMenu` do Windows chuyển vào khi người dùng click chuột phải vào nút icon.
  2. Đọc trạng thái hiện tại từ `BridgeStateManager` (đang là Telex hay VNI, Unicode hay TCVN3).
  3. Lần lượt gọi `pMenu->AddMenuItem(uId, dwFlags, hbmp, hbmpMask, pch, cch, ppSubMenu)` để thêm từng dòng vào menu kèm cờ trạng thái (`TF_LBMENUFLAG_CHECKED`, `TF_LBMENUFLAG_SUBMENU`, `TF_LBMENUFLAG_SEPARATOR`).
- **Hàm `OnMenuSelect(uint uId)`:**
  1. Windows trả về ID của mục người dùng vừa chọn.
  2. Dùng cấu trúc `switch-case` tương ứng với các hằng số:
     - Nếu chọn kiểu gõ: Cập nhật kiểu gõ mới vào F# State Machine.
     - Nếu chọn bảng mã: Cập nhật cờ chuyển đổi chuỗi đầu ra.
     - Nếu chọn "Tùy chọn cấu hình...": Gọi hàm mở cửa sổ Settings GUI.
  3. Lưu trạng thái mới vào file cấu hình đệm để bảo lưu thiết lập.

**4. Checkpoint kiểm thử:**

- Click chuột phải vào icon Taskbar, menu pop-up phải hiện lên chuẩn font Unicode tiếng Việt không bị lỗi font/dấu hỏi (`?`).
- Tick chọn chuyển sang VNI, gõ thử số `1, 2, 3` để kiểm tra F# Engine đã nhận lệnh chuyển kiểu gõ chưa.

### Bước 4 (`003_04_SharedConfiguration_Schema.md`): Chuẩn hóa Schema cấu hình dùng chung (`config.json`)

**1. Mục tiêu kiến trúc**

- Tách biệt hoàn toàn tầng lưu trữ dữ liệu cấu hình khỏi API nền tảng để sau này chia sẻ dùng chung giữa Windows (NativeBridge) và Linux (Fcitx5 Addon).
- File cấu hình lưu dưới dạng JSON chuẩn tại đường dẫn tiêu chuẩn:
  - Windows: `%AppData%\BambooMintKey\config.json`
  - Linux: `~/.config/bamboomintkey/config.json`

**2. Thiết kế Data Contract (JSON Schema)**

- Cấu trúc JSON chuẩn:

  JSON

  ```
  {
    "version": 1,
    "inputMethod": "Telex",
    "charset": "Unicode",
    "toggleHotkey": "CtrlShift",
    "spellCheck": true,
    "autoRestoreIfInvalid": true,
    "useModernOrthography": true,
    "macroEnabled": false,
    "macros": {
      "vn": "Việt Nam",
      "bmk": "BambooMintKey"
    }
  }
  ```

**3. Quy trình xử lý ở tầng F# Core (`BambooMintKey.Core`)**

- Tạo module `EngineConfig.fs` với các Discriminated Unions và Record types thuần:
  - `type InputMethod = Telex | Vni | SimpleTelex`
  - `type Charset = Unicode | CompoundUnicode | Tcvn3`
  - `type ToggleHotkey = CtrlShift | AltZ`
  - `type EngineConfig = { ... }`
- Viết parser JSON tối giản (sử dụng tokenizer đơn giản hoặc serializer native không kéo theo dependency nặng) để nạp nội dung tệp vào memory state.
- Cung cấp hàm thuần chức năng: `Engine.updateConfig: EngineConfig -> EngineState -> EngineState`.

**4. Cơ chế đồng bộ hóa Hot-Reload ở NativeBridge**

- Tạo một luồng ngầm sử dụng Win32 `ReadDirectoryChangesW` (hoặc `FileSystemWatcher` trong C#) theo dõi thư mục `%AppData%\BambooMintKey\`.
- Khi phát hiện sự kiện file `config.json` được ghi đè (từ Settings GUI hoặc người dùng sửa tay):
  1. Chờ 50ms (debounce) để tránh xung đột file lock.
  2. Đọc chuỗi nội dung mới.
  3. Đẩy dữ liệu cấu hình vào `BridgeStateManager`.
  4. Bắn sự kiện cập nhật Taskbar (nếu phím tắt hoặc trạng thái hiển thị thay đổi).

**5. Checkpoint kiểm thử:**

- Thử mở `config.json` bằng Notepad, sửa `"inputMethod": "Vni"`, lưu lại.
- Gõ thử ngay trên cửa sổ soạn thảo mà không khởi động lại bộ gõ, xác nhận engine tự động chuyển sang chế độ VNI.

### Bước 5 (`003_05_SettingsGUI_FnConfigure.md`): Tích hợp COM `ITfFnConfigure` và cửa sổ Cài đặt độc lập

**1. Cơ sở chuẩn hóa từ Windows SDK**

- File định nghĩa: `msctf.idl`.
- **GUID chuẩn:**
  - `ITfFunctionProvider`: `101D9462-0E4E-41F1-B34B-E1EF37E02F0D`
  - `ITfFnConfigure`: `88F567C6-1757-49F8-A1B2-89234C1EEFF9`
- Đây là interface chuẩn để nút **Options** trong mục cài đặt ngôn ngữ của Windows (`Settings -> Time & Language -> Language -> BambooMintKey -> Options`) có thể bấm được thay vì bị xám mờ.

**2. Quy trình triển khai `ITfFnConfigure` trong NativeBridge**

- Khai báo VTable cho `ITfFunctionProvider` và `ITfFnConfigure`.
- Khi `ActivateEx` chạy: Đăng ký `FunctionProvider` với `ITfThreadMgr` thông qua hàm `ITfSourceSingle::AdviseSingleSink`.
- Cài đặt hàm `ITfFnConfigure::Show(HWND hwndParent, LANGID langid, REFGUID rguidProfile)`:
  1. Hàm này được Windows gọi khi người dùng bấm nút Options trong Windows Settings hoặc chọn từ context menu Taskbar.
  2. Tìm đường dẫn thực thi của ứng dụng GUI cấu hình (`BambooMintKey.Config.exe`) nằm cùng thư mục hoặc trong thư mục cài đặt.
  3. Dùng Win32 API `CreateProcessW` khởi chạy tiến trình `BambooMintKey.Config.exe` với tham số `--parent-hwnd <hwndParent>`.
  4. Trả về `HRESULT = S_OK`.

**3. Xây dựng ứng dụng GUI Cài đặt độc lập (`BambooMintKey.Config`)**

- **Công nghệ:** Project C# riêng biệt sử dụng **Avalonia UI** (biên dịch NativeAOT để mở tức thì với dung lượng dưới 15MB, đồng thời chia sẻ 100% mã XAML/C# khi đem qua Linux).
- **Bố cục giao diện:**
  - **Tab 1 - Điều khiển cơ bản:** Radio button chọn kiểu gõ (Telex/VNI), Radio button chọn bảng mã, Dropdown chọn phím tắt chuyển chế độ (`Ctrl + Shift` / `Alt + Z`).
  - **Tab 2 - Tùy chọn nâng cao:** Checkbox bật/tắt chính tả, Checkbox đặt dấu tự do, Checkbox khôi phục từ khi xóa dấu.
  - **Tab 3 - Bảng gõ tắt (Macro):** Giao diện bảng (DataGrid) hiển thị danh sách từ viết tắt; các nút Thêm, Sửa, Xóa; nút Nhập/Xuất file macro text.
- **Xử lý sự kiện nút "Lưu thay đổi":**
  1. Đọc dữ liệu từ form giao diện.
  2. Validate tính hợp lệ của các trường.
  3. Ghi đè vào file `%AppData%\BambooMintKey\config.json`.
  4. Đóng cửa sổ ứng dụng. File watcher tại Bước 4 sẽ tự động làm phần việc còn lại để cập nhật engine.

**4. Checkpoint kiểm thử:**

- Mở Windows Settings -> Language -> Vietnamese -> BambooMintKey -> Nút **Options** sáng lên và click được.
- Bấm vào nút Options, cửa sổ Cài đặt Avalonia bật lên mượt mà không làm treo cửa sổ Settings của Windows.
- Thêm một từ gõ tắt mới trong GUI, bấm Lưu, ra ngoài gõ thử từ viết tắt để xác nhận từ mới đã được nạp thành công.

Cấu trúc trên đã khép kín toàn bộ quy trình từ Windows SDK IDL gốc, cài đặt COM VTable, Win32 GDI, F# Core binding cho đến ứng dụng GUI độc lập. Bạn muốn bắt đầu tạo tài liệu chi tiết và mã nguồn cho **Bước 1** ngay chưa?
