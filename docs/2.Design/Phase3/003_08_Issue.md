# 003_08_Issue.md — Icon Taskbar V/E của BambooMintKey bị "lúc được lúc mất"

> Trạng thái: Open  
> Mức độ: High  
> Phạm vi: `BambooMintKey.NativeBridge.TSF.LangBarItemButton`, `BambooMintKey.NativeBridge.TSF.IconHelper`, `BambooMintKey.NativeBridge.TSF.BridgeStateManager`  
> Log phân tích: `docs/2.Design/Phase3/BambooMintKey_Runtime.log`  

## 1. Tóm tắt vấn đề

Biểu tượng Taskbar Language Bar (icon chữ **V** / **E**) của BambooMintKey xuất hiện hành vi không ổn định:

- Có lúc click chuột trái vào icon đổi trạng thái đúng.
- Có lúc click xong chế độ đã đảo trong engine nhưng icon trên Taskbar không đổi theo.
- Icon đôi khi biến mất hoặc giật/flicker.

Điểm quan trọng: **bộ gõ tiếng Việt vẫn hoạt động bình thường** — các ký tự Telex được xử lý và commit đúng. Lỗi chỉ nằm ở lớp hiển thị / đồng bộ icon Taskbar Language Bar, không phải engine xử lý gõ.

### 2.5. Không có log `AdviseSink` thành công từ `LangBarItemButton`

Trong toàn bộ log, không có dòng nào ghi nhận `LangBarItemButton.AdviseSink ENTER ... ITfLangBarItemSink connected`. Điều này có nghĩa:

- Hoặc Windows chưa bao giờ gọi `AdviseSink` với `IID_ITfLangBarItemSink` thành công.
- Hoặc log path trong `AdviseSink` không được ghi vì các nhánh khác được thực thi trước.

Dòng log duy nhất liên quan đến `AdviseSink` là từ một thành phần khác (không phải `LangBarItemButton`), với IID khác:

```log
[15:59:47.265] AdviseSink(IID=aa80e80e-2021-11d2-93e0-0060b067b86e) HR=0x00000000, cookie=67108866
```

IID này là `IID_ITfThreadMgrEventSink`, không phải `IID_ITfLangBarItemSink`.

## 3. Phân tích mã nguồn liên quan

### 3.1. `LangBarItemButton.NotifyStateChanged`

File: `src/BambooMintKey.NativeBridge/TSF/LangBarItemButton.cs` (dòng 456–472)

```csharp
public static void NotifyStateChanged()
{
    DebugLog.Write($"LangBarItemButton.NotifyStateChanged ENTER _pLangBarSink={_pLangBarSink}, thread={Environment.CurrentManagedThreadId}");
    if (_pLangBarSink != IntPtr.Zero)
    {
        var sinkVTable = *(ITfLangBarItemSinkVTable**)_pLangBarSink;
        int hr = sinkVTable->OnUpdate(
            _pLangBarSink,
            TsfLangBarFlags.TfLbiIcon | TsfLangBarFlags.TfLbiText | TsfLangBarFlags.TfLbiTooltip);
        DebugLog.Write($"LangBarItemButton.NotifyStateChanged: OnUpdate sent to Windows Taskbar hr=0x{hr:X8}");
    }
    else
    {
        DebugLog.Write("LangBarItemButton.NotifyStateChanged: _pLangBarSink is NULL, cannot notify");
    }
}
```

Hàm này phụ thuộc hoàn toàn vào `_pLangBarSink`. Nếu sink chưa được Windows trao (NULL), thông báo cập nhật icon sẽ bị bỏ qua. Log đã xác nhận điều này xảy ra 2 lần ngay khi khởi động.

### 3.2. `LangBarItemButton.AdviseSink`

File: `src/BambooMintKey.NativeBridge/TSF/LangBarItemButton.cs` (dòng 252–301)

Đoạn code nhận sink từ Windows có dòng:

```csharp
var unk = *(TfSourceVTable**)punk;
int hrQi = unk->QueryInterface(punk, &iidSink, &pSink);
```

`punk` là con trỏ `IUnknown*` do Windows truyền vào. Code cast nó trực tiếp thành con trỏ vtable (`TfSourceVTable**`) và gọi `QueryInterface` qua layout đó. Đây là hành vi không được đảm bảo bởi COM contract. Nếu layout vtable trùng khớp tình cờ thì chạy, nếu không thì `QueryInterface` có thể trỏ đến vùng nhớ sai hoặc trả về kết quả không xác định.

Sau đó code fallback:

```csharp
_pLangBarSink = punk;
NativeCom.AddRef(punk);
```

Lưu trực tiếp `punk` (một `IUnknown*`) vào `_pLangBarSink`, sau đó lại sử dụng nó như thể nó là `ITfLangBarItemSink*` trong `NotifyStateChanged`:

```csharp
var sinkVTable = *(ITfLangBarItemSinkVTable**)_pLangBarSink;
int hr = sinkVTable->OnUpdate(_pLangBarSink, ...);
```

Nếu `punk` thực sự là `IUnknown` của `ITfLangBarItemSink`, việc cast sang vtable của `ITfLangBarItemSink` có thể đúng; nhưng nếu `punk` là `IUnknown` của đối tượng khác, việc gọi `OnUpdate` theo vtable của `ITfLangBarItemSink` sẽ sai.

### 3.3. `LangBarItemButton.GetIcon`

File: `src/BambooMintKey.NativeBridge/TSF/LangBarItemButton.cs` (dòng 219–234)

```csharp
private static int GetIcon(IntPtr thisPtr, IntPtr* phIcon)
{
    if (phIcon == null) return HResult.InvalidArgument;
    string text = BridgeStateManager.IsVietnameseMode ? "V" : "E";
    DebugLog.Write($"LangBarItemButton.GetIcon ENTER requested='{text}', IsVietnameseMode={BridgeStateManager.IsVietnameseMode}, thread={Environment.CurrentManagedThreadId}");
    *phIcon = IconHelper.CreateBambooIcon(text);
    DebugLog.Write($"LangBarItemButton.GetIcon EXIT text='{text}' -> {*phIcon}, CreationCount={IconHelper.CreationCount}, FailureCount={IconHelper.FailureCount}, LastWin32Error={IconHelper.LastWin32Error}");
    return HResult.Ok;
}
```

Mỗi lần Windows gọi `GetIcon`, code đều tạo một `HICON` mới hoàn toàn qua `IconHelper.CreateBambooIcon`. Không có cache theo trạng thái hoặc theo DPI. Điều này giải thích con số 705 icon được tạo.

### 3.4. `IconHelper.CreateBambooIcon`

File: `src/BambooMintKey.NativeBridge/TSF/IconHelper.cs` (dòng 159–287)

Hàm này thực hiện đầy đủ pipeline GDI mỗi lần gọi:

1. `GetDC(0)`
2. `CreateCompatibleDC` + `CreateCompatibleBitmap` (color)
3. `CreateSolidBrush`, `CreatePen`, `CreateFontW`
4. `RoundRect` + `DrawTextW`
5. `CreateCompatibleDC` + `CreateBitmap` (mask 1-bit)
6. `CreateIconIndirect`
7. Cleanup toàn bộ GDI object

Mặc dù cleanup được thực hiện, việc tạo 705 icon trong phiên ngắn tạo áp lực lớn lên handle pool và có thể gây flicker/mất icon trong các giai đoạn Windows Taskbar bận hoặc khi explorer restart.

### 3.5. `BridgeStateManager.IsVietnameseMode`

File: `src/BambooMintKey.NativeBridge/TSF/BridgeStateManager.cs` (dòng 47–52)

```csharp
public static bool IsVietnameseMode
{
    get => SharedMemoryManager.IsVietnameseMode;
    set => SharedMemoryManager.IsVietnameseMode = value;
}
```

Giá trị này được đọc từ shared memory. Nó được sử dụng bởi:

- Thread chính TSF (`OnClick`, `GetIcon`, log ghi `thread=2`).
- Background thread `StartEventListener` (kiểm tra mỗi 100ms).
- Windows Taskbar thread khi gọi `GetIcon`.

Không có cơ chế đồng bộ (`lock`, `Interlocked`, `volatile`) cho `_pLangBarSink`, `_sinkCookie`, hay `IsVietnameseMode` giữa các thread.

### 3.6. `StartEventListener`

File: `src/BambooMintKey.NativeBridge/TSF/LangBarItemButton.cs` (dòng 326–375)

Background thread này:

- Chờ event thay đổi trạng thái tối đa 100ms.
- So sánh `currentMode` với `lastMode`.
- Nếu khác, gọi `NotifyStateChanged()`.

Log xác nhận các lần `OnUpdate sent ...` sau 16:00 đều phát sinh từ cơ chế này, không phải từ click chuột trực tiếp.

## 4. Nhận diện root cause

Dựa trên log và source code, có 4 nhóm nguyên nhân chính dẫn đến hiện tượng icon "lúc được lúc mất":

### 4.1. Race condition: click icon trước khi sink được kết nối

- Windows chưa gọi `AdviseSink(IID_ITfLangBarItemSink)` hoặc chưa truyền sink hợp lệ.
- Người dùng đã click icon → `OnClick` gọi `NotifyStateChanged()`.
- `_pLangBarSink == NULL` → `OnUpdate` không gửi được → Taskbar không vẽ lại.
- Kết quả: chế độ engine đã đảo, icon trên màn hình không đổi.

Log chứng cứ: dòng 4, 9 — `_pLangBarSink is NULL, cannot notify` xuất hiện ngay trong 2 lần click đầu tiên.

### 4.2. Con trỏ COM trong `AdviseSink` bị cast sai

- `punk` là `IUnknown*`.
- Code cast thành `TfSourceVTable**` và gọi `QueryInterface` trực tiếp, vi phạm COM contract.
- Nếu layout vtable không khớp, `_pLangBarSink` có thể trỏ đến vùng nhớ không hợp lệ hoặc `QueryInterface` trả về giá trị không xác định.
- Đây là lý do tại sao `_pLangBarSink` đôi khi hoạt động (gửi `OnUpdate` 14 lần thành công), đôi khi lại NULL hoặc không ổn định.

### 4.3. Tạo icon mới mỗi lần `GetIcon` — không cache

- Windows Taskbar yêu cầu `GetIcon` nhiều lần (redraw, hover, DPI change, animation...).
- Bộ gõ tạo 705 icon mới trong phiên ngắn.
- Việc này:
  - Tạo áp lực lên GDI handle pool.
  - Gây flicker khi Taskbar vẽ lại.
  - Có thể làm icon tạm biến mất nếu Windows không kịp xử lý / hủy handle cũ.

### 4.4. Thiếu đồng bộ đa luồng

- `_pLangBarSink`, `_sinkCookie`, `BridgeStateManager.IsVietnameseMode` được đọc/ghi từ ít nhất 3 thread khác nhau.
- Không có `lock`, `Interlocked`, hay `volatile`.
- Có khả năng race condition nhỏ khi `OnClick` (thread TSF) và `StartEventListener` (background) cùng gọi `NotifyStateChanged()`, hoặc khi `GetIcon` đọc `IsVietnameseMode` trong khi `OnClick` đang ghi.

## 5. Impact (tác động)

| Khía cạnh | Mô tả |
|---|---|
| UX | Người dùng không biết chế độ gõ hiện tại là V hay E; click icon có thể không phản hồi. |
| Độ tin cậy | Icon biến mất/giật trong các tình huống Taskbar redraw nhiều (DPI change, remote desktop, explorer restart). |
| Hiệu năng | 705 lần tạo icon GDI trong phiên ngắn, tiềm ẩn GDI handle pressure và memory churn. |
| Engine | Không ảnh hưởng. Bộ gõ vẫn xử lý Telex chính xác. |

## 6. Điều kiện tái hiện

1. Đăng ký và kích hoạt BambooMintKey trong một ứng dụng (ví dụ Notepad).
2. Quan sát icon Taskbar Language Bar.
3. Click chuột trái nhanh vào icon ngay khi bộ gõ vừa hiển thị.
4. Thay đổi focus giữa các ứng dụng hoặc đổi DPI để kích thích Taskbar redraw.
5. Quan sát icon đôi khi không đổi theo chế độ thực tế.
