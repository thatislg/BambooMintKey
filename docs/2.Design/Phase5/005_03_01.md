## 1. Hiện Trạng & Bài Toán Kỹ Thuật (Problem Statement & Scope)

### 1.1. Hiện tượng lỗi (Bug Description)
Trong tài liệu [005_03_Auto-capitalization-after-uppercase-D.md](file:///D:/Kojin/BambooMintKey/docs/2.Design/Phase5/005_03_Auto-capitalization-after-uppercase-D.md), người dùng phản ánh hiện tượng:
- Khi gõ các từ bắt đầu bằng chữ cái tiếng Việt có dấu phụ viết hoa (`Đ`, `Ê`, `Ă`, `Â`, `Ô`) và các ký tự tiếp theo trong từ được gõ ở dạng chữ thường (không giữ phím `Shift`), kết quả thực tế trên màn hình lại bị **viết hoa toàn bộ (ALL-CAPS)** thay vì viết hoa chữ cái đầu (Title Case).

| Chuỗi phím gõ thực tế | Kỳ vọng (Expected) | Thực tế bị lỗi (Actual Bug) | Đánh giá trạng thái |
|---|---|---|---|
| `Ddi` hoặc `DDi` + Space | `Đi ` | `ĐI ` | ❌ Lỗi nghiêm trọng |
| `Eem` hoặc `EEm` + Space | `Êm ` | `ÊM ` | ❌ Lỗi nghiêm trọng |
| `Awn` hoặc `AWn` + Space | `Ăn ` | `ĂN ` | ❌ Lỗi nghiêm trọng |
| `Aan` hoặc `AAn` + Space | `Ân ` | `ÂN ` | ❌ Lỗi nghiêm trọng |
| `Oon` hoặc `OOn` + Space | `Ôn ` | `ÔN ` | ❌ Lỗi nghiêm trọng |
| `Om` + Space | `Om ` | `Om ` | ✅ Hoạt động đúng |
| `Ung` + Space | `Ung ` | `Ung ` | ✅ Hoạt động đúng |
| `Owm` + Space | `Ơm ` | `Ơm ` | ✅ Hoạt động đúng |
| `Own` + Space | `Ơn ` | `Ơn ` | ✅ Hoạt động đúng |
| `Uwong` + Space | `Ương ` | `Ương ` | ✅ Hoạt động đúng |

Cách người dùng phải khắc phục tạm thời (workaround) hiện nay:
- Gõ `Ddi` + Space $\rightarrow$ xuất hiện `ĐI `
- Nhấn `Backspace` hai lần $\rightarrow$ xóa chữ `I` và khoảng trắng, còn lại `Đ`
- Gõ tiếp `i` $\rightarrow$ ra `Đi`.
Thao tác này làm suy giảm nghiêm trọng trải nghiệm soạn thảo văn bản, gây khó chịu cho người sử dụng khi nhập liệu danh từ riêng hoặc đầu câu.

## 2. Phân Tích Cội Rễ Kỹ Thuật (Deep Technical Root Cause Analysis)

Để tìm ra lý do tại sao nhóm từ **`ĐI`, `ÊM`, `ĂN`, `ÂN`, `ÔN` bị lỗi**, trong khi nhóm từ **`Ơm`, `Ơn`, `Ương`, `Ung`, `Om` lại hoạt động hoàn toàn chính xác**, chúng tôi đã điều tra chéo giữa hai tầng kiến trúc:
1. Tầng **Windows TSF / Win32 Native Layer** (`BambooMintKey.NativeBridge`).
2. Tầng **F# Pure Core Engine** (`BambooMintKey.Core`).

Kết quả điều tra xác định có **HAI NGUYÊN NHÂN TƯƠNG HỖ (DUAL ROOT CAUSES)** dẫn đến lỗi này:

```
[Người dùng gõ bàn phím]
          │
          ▼
┌────────────────────────────────────────────────────────────────────────┐
│ NGUYÊN NHÂN 1: TSF Layer (KeyInputTranslator.ConvertVirtualKeyToChar)   │
│ - GetKeyboardState() đọc trạng thái từ Thread Message Queue.           │
│ - Khi TSF nuốt phím (*pfEaten = 1), thông điệp WM_KEYUP của Shift      │
│   không được message loop xử lý kịp thời.                              │
│ - Kết quả: keyState[VK_SHIFT] vẫn bị giữ giá trị 0x80 (Stuck Shift).   │
│ - ToUnicode biến các phím gõ sau thành chữ HOA!                        │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ Raw keys: ['D', 'D', 'i'] hoặc ['D', 'D', 'I']
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ NGUYÊN NHÂN 2: Core Engine Layer (WordBuffer.detectCase & applyCase)   │
│ - Thói quen người dùng gõ chữ hoa Telex: giữ Shift khi nhấn đúp phím   │
│   modifier đầu từ (Shift + DD -> 'D','D'; Shift + EE -> 'E','E'...).   │
│ - detectCase thấy letters[1] là chữ hoa -> Đánh giá nhầm sang Mixed!   │
│ - applyCase quét 1-to-1 giữa pattern và transformed.                   │
│   Vì 'DD' gộp thành 'Đ' (2 ký tự thành 1), bit HOA của chữ 'D' thứ hai │
│   bị LỆCH CHỈ SỐ (Off-by-One) đè lên ký tự 'i' tiếp theo!              │
│ - Kết quả: "Đi" bị biến thành "ĐI"!                                   │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1. Cội rễ 1: Sự mất đồng bộ trạng thái Shift trong TSF Layer (`KeyInputTranslator.cs`)

Trong tệp `src/BambooMintKey.NativeBridge/Interop/KeyInputTranslator.cs`:
```csharp
public static char? ConvertVirtualKeyToChar(UIntPtr wParam, IntPtr lParam)
{
    uint vkCode = (uint)wParam;
    uint scanCode = ((uint)lParam >> 16) & 0xFF;

    byte[] keyState = new byte[256];
    if (!GetKeyboardState(keyState)) return null;

    var sb = new System.Text.StringBuilder(4);
    int result = ToUnicode(vkCode, scanCode, keyState, sb, sb.Capacity, 0);
    ...
}
```

#### Cơ chế hoạt động của `GetKeyboardState` trong Win32:
- Hàm API `GetKeyboardState` sao chép trạng thái 256 phím ảo từ **hàng đợi thông điệp (Message Queue) của luồng hiện tại**.
- Trạng thái này chỉ được Windows kernel cập nhật khi luồng rút thông điệp bàn phím (`WM_KEYDOWN`, `WM_KEYUP`) thông qua các hàm `GetMessage` hoặc `PeekMessage`.

#### Xung đột với TSF (Text Services Framework):
1. Trong Windows TSF, khi người dùng gõ phím, `msctf.dll` gọi trực tiếp vào COM callback `ITfKeyEventSink::OnTestKeyDown` và `ITfKeyEventSink::OnKeyDown`.
2. Khi BambooMintKey xử lý ký tự và trả về `*pfEaten = 1`, TSF **nuốt phím** và ngăn Windows dispatch thông điệp đó vào Window Message Loop của ứng dụng.
3. Khi người dùng nhả phím `Shift`, nếu thao tác gõ diễn ra nhanh hoặc thông điệp nhả phím chưa kịp bơm qua message loop trước lần gọi `OnKeyDown` tiếp theo:
   - `GetKeyboardState(keyState)` vẫn đọc được trạng thái cũ với `keyState[VK_SHIFT] = 0x80` (trạng thái Shift bị "kẹt ảo" - Dead Shift State).
   - Hàm `ToUnicode` tiếp tục áp dụng trạng thái Shift lên phím tiếp theo, biến `d` $\rightarrow$ `D`, `i` $\rightarrow$ `I`, `m` $\rightarrow$ `M`.
4. Đáng chú ý, trong cùng tệp `KeyInputTranslator.cs` (dòng 118-124), hàm `IsKeyDown` đã dùng đến `GetAsyncKeyState`:
   ```csharp
   private static bool IsKeyDown(int vKey)
   {
       return ((GetKeyState(vKey) & 0x8000) != 0) || ((GetAsyncKeyState(vKey) & 0x8000) != 0);
   }
   ```
   Hàm `GetAsyncKeyState` truy vấn **trạng thái vật lý phần cứng thực tế tại thời điểm gọi**, hoàn toàn độc lập với message queue! Nhưng hàm `ConvertVirtualKeyToChar` lại chưa hề tận dụng `GetAsyncKeyState` để đồng bộ lại mảng `keyState`.

### 2.2. Cội rễ 2: Lệch chỉ số Pattern (Off-by-One) và Nhận Diện Case Thiếu Trong `WordBuffer.fs`

Ngay cả khi người dùng cố tình hoặc vô tình giữ Shift khi gõ phím modifier thứ hai (hành vi gõ cực kỳ phổ biến ở người dùng Việt Nam: `Shift + D + D` để gõ `Đ`, `Shift + E + E` để gõ `Ê`, `Shift + A + A` để gõ `Â`, `Shift + O + O` để gõ `Ô`, `Shift + A + W` để gõ `Ă`), tầng lõi F# `WordBuffer.fs` xuất hiện 2 lỗi nghiêm trọng:

#### A. `WordBuffer.detectCase` đánh giá sai sang `LetterCase.Mixed`:
Trong `src/BambooMintKey.Core/Engine/WordBuffer.fs`:
```fsharp
let detectCase (rawKeys: char list) : LetterCase =
    if rawKeys.IsEmpty then LetterCase.Lower
    else
        let letters = rawKeys |> List.filter Char.IsLetter
        if letters.IsEmpty then LetterCase.Lower
        elif letters |> List.forall Char.IsUpper then LetterCase.Upper
        elif Char.IsUpper letters.Head && (letters.Tail |> List.forall Char.IsLower) then LetterCase.Title
        elif letters |> List.forall Char.IsLower then LetterCase.Lower
        else
            LetterCase.Mixed (rawKeys |> List.map Char.IsUpper)
```
- Khi người dùng gõ `DDi` (`['D', 'D', 'i']`):
  - `letters.Head` = `'D'` (chữ hoa).
  - `letters.Tail` = `['D', 'i']`. Điều kiện `letters.Tail |> List.forall Char.IsLower` bị **SAI** (vì phần tử đầu tiên của `Tail` là `'D'`).
  - Do đó, engine không nhận diện đây là `LetterCase.Title`, mà rơi xuống nhánh `else`:
    `LetterCase.Mixed [true; true; false]`.

#### B. `WordBuffer.applyCase` bị lệch chỉ số do độ dài Telex co rút:
Trong `WordBuffer.fs`:
```fsharp
| LetterCase.Mixed pattern ->
    let chars = transformed.ToCharArray()
    let len = chars.Length
    for i = 0 to min (len - 1) (pattern.Length - 1) do
        if pattern[i] then
            chars[i] <- Char.ToUpperInvariant chars[i]
        else
            chars[i] <- Char.ToLowerInvariant chars[i]
    String chars
```
- `pattern` được tạo từ `rawKeys` `['D', 'D', 'i']` $\rightarrow$ có độ dài là **3**: `[true; true; false]`.
- `transformed` sau khi giải phóng modifier `DD` thành `Đ` chỉ có độ dài là **2**: `"Đi"`.
- Vòng lặp `for i = 0 to min (2 - 1) (3 - 1)` duyệt qua:
  - `i = 0`: `pattern[0]` là `true` $\rightarrow$ `chars[0]` (`'Đ'`) giữ nguyên chữ HOA $\rightarrow$ `'Đ'`.
  - `i = 1`: `pattern[1]` (vốn là cờ Shift của chữ `'D'` thứ hai!) là `true` $\rightarrow$ **`chars[1]` (`'i'`) bị ép thành chữ HOA `'I'`**!
  - `i = 2`: `pattern[2]` là `false` (vốn thuộc về `'i'`) **hoàn toàn bị bỏ qua vì vượt quá độ dài chuỗi `transformed`**!
- **Kết quả trả về:** `"Đi"` bị ép thành `"ĐI"`!

#### Tại sao `Om`, `Ung`, `Ơm`, `Ơn`, `Ương` lại KHÔNG bị lỗi?
1. **`Om`** (`['O', 'm']`) & **`Ung`** (`['U', 'n', 'g']`): Chữ cái đầu chỉ gồm 1 phím gõ duy nhất (`O`, `U`). Phím tiếp theo (`m`, `n`) gõ thường. `letters.Tail` gồm toàn chữ thường $\rightarrow$ `detectCase` nhận diện đúng `LetterCase.Title` $\rightarrow$ Không kích hoạt nhánh `Mixed` $\rightarrow$ Ra `Om`, `Ung`.
2. **`Owm`** (`['O', 'w', 'm']`) & **`Own`** (`['O', 'w', 'n']`) & **`Uwong`** (`['U', 'w', 'o', 'n', 'g']`):
   - Trên bàn phím chuẩn US, phím `O` và `U` nằm bên tay phải, còn phím `w` nằm bên tay trái.
   - Khi gõ `Ow` hoặc `Uw`, người dùng thường nhả `Shift` tay trái trước khi nhấn phím `w` bằng ngón tay trái. Do đó phím `w` được ghi nhận là chữ thường `'w'`.
   - Chuỗi thô là `['O', 'w', 'm']`. `letters.Head` = `'O'`, `letters.Tail` = `['w', 'm']` (toàn chữ thường!) $\rightarrow$ `detectCase` nhận diện đúng `LetterCase.Title` $\rightarrow$ Ra `Ơm`, `Ơn`, `Ương`.
3. Ngược lại, với **`Ddi`/`DDi`**, **`Eem`/`EEm`**, **`Aan`/`AAn`**, **`Oon`/`OOn`**:
   - Hai phím tạo nên chữ cái đầu là **cùng một phím vật lý được gõ liên tiếp (Double-Tap)**: `D-D`, `E-E`, `A-A`, `O-O`.
   - Khi người dùng nhấn giữ `Shift` để gõ chữ hoa, họ thường giữ `Shift` trong suốt cả 2 lần gõ của phím đó.
   - Và nếu người dùng có nhả Shift giữa 2 lần gõ cực nhanh, `GetKeyboardState` của TSF vẫn kẹt bit `0x80`, biến lần gõ thứ hai thành chữ hoa!

## 4. Thiết Kế Chi Tiết & Cài Đặt Kỹ Thuật (Detailed Implementation Specs)

### 4.1. Tầng 1: NativeBridge - Đồng bộ trạng thái phần cứng Shift (`KeyInputTranslator.cs`)

Trong `src/BambooMintKey.NativeBridge/Interop/KeyInputTranslator.cs`, tại hàm `ConvertVirtualKeyToChar`:

```csharp
public static char? ConvertVirtualKeyToChar(UIntPtr wParam, IntPtr lParam)
{
    uint vkCode = (uint)wParam;
    uint scanCode = ((uint)lParam >> 16) & 0xFF;

    byte[] keyState = new byte[256];
    if (!GetKeyboardState(keyState)) return null;

    // -------------------------------------------------------------------------
    // BẢO VỆ ĐỒNG BỘ TRẠNG THÁI PHÍM SHIFT (HARDWARE-SYNC SHIFT STATE)
    // -------------------------------------------------------------------------
    // GetKeyboardState() đọc từ thread message queue và có thể bị trễ / kẹt 0x80
    // khi TSF nuốt phím (*pfEaten = 1) hoặc khi nhả phím Shift nhanh.
    // Dùng GetAsyncKeyState() để phản ánh chính xác trạng thái vật lý thực tế.
    bool isShiftPhysicallyDown = (GetAsyncKeyState((int)VkShift) & 0x8000) != 0;
    if (!isShiftPhysicallyDown)
    {
        keyState[VkShift] = 0;
        keyState[0xA0] = 0; // VK_LSHIFT
        keyState[0xA1] = 0; // VK_RSHIFT
    }
    else
    {
        keyState[VkShift] = 0x80;
    }

    var sb = new System.Text.StringBuilder(4);
    int result = ToUnicode(vkCode, scanCode, keyState, sb, sb.Capacity, 0);

    if (result > 0 && sb.Length > 0)
    {
        return sb[0];
    }

    return null;
}
```

### 4.2. Tầng 2: F# Core Engine - Nhận diện TitleCase cho Modifier kép (`WordBuffer.fs`)

Trong `src/BambooMintKey.Core/Engine/WordBuffer.fs`:

#### A. Hàm kiểm tra cặp ký tự modifier kép đầu từ:
```fsharp
let private isInitialDoubleModifierPair (c1: char) (c2: char) : bool =
    let pair = String [| Char.ToLowerInvariant c1; Char.ToLowerInvariant c2 |]
    match pair with
    | "dd" | "ee" | "aa" | "oo" | "aw" | "ow" | "uw" -> true
    | _ -> false
```

#### B. Cập nhật `detectCase`:
```fsharp
let detectCase (rawKeys: char list) : LetterCase =
    if rawKeys.IsEmpty then LetterCase.Lower
    else
        let letters = rawKeys |> List.filter Char.IsLetter
        if letters.IsEmpty then LetterCase.Lower
        elif letters |> List.forall Char.IsUpper then LetterCase.Upper
        // Trường hợp Title tiêu chuẩn: 1 ký tự đầu viết hoa, các ký tự sau viết thường
        elif Char.IsUpper letters.Head && (letters.Tail |> List.forall Char.IsLower) then LetterCase.Title
        // Trường hợp Title với modifier kép đầu từ: ví dụ 'DD'i, 'EE'm, 'AA'n, 'OO'n, 'AW'n...
        // Người dùng gõ chữ cái đầu bằng 2 phím trong khi giữ Shift, sau đó nhả Shift gõ chữ thường.
        elif letters.Length >= 2 &&
             isInitialDoubleModifierPair letters[0] letters[1] &&
             Char.IsUpper letters[0] &&
             (letters |> List.skip 2 |> List.forall Char.IsLower) then
            LetterCase.Title
        elif letters |> List.forall Char.IsLower then LetterCase.Lower
        else
            LetterCase.Mixed (rawKeys |> List.map Char.IsUpper)
```

#### C. Hoàn thiện `applyCase` để bảo vệ trường hợp `Mixed`:
```fsharp
let applyCase (letterCase: LetterCase) (transformed: string) : string =
    if String.IsNullOrEmpty transformed then transformed
    else
        match letterCase with
        | LetterCase.Lower -> transformed.ToLowerInvariant()
        | LetterCase.Upper -> transformed.ToUpperInvariant()
        | LetterCase.Title ->
            if transformed.Length = 1 then transformed.ToUpperInvariant()
            else
                string (Char.ToUpperInvariant transformed[0]) + transformed[1..].ToLowerInvariant()
        | LetterCase.Mixed pattern ->
            let chars = transformed.ToCharArray()
            let len = chars.Length
            
            // Xử lý bù trừ vị trí khi ký tự đầu được tạo từ modifier kép
            // Nếu transformed bắt đầu bằng ký tự biến đổi từ 2 raw keys (như Đ, Ê, Â, Ô, Ă, Ơ, Ư)
            let startsWithContractedChar =
                len > 0 && pattern.Length >= 2 &&
                isInitialDoubleModifierPair (if pattern[0] then 'D' else 'd') (if pattern[1] then 'D' else 'd')

            // Duyệt gán hoa/thường chuẩn xác
            for i = 0 to len - 1 do
                let patternIdx =
                    if startsWithContractedChar && i > 0 then
                        // Ký tự từ vị trí 1 trở đi trong transformed ứng với raw key từ vị trí 2 trở đi
                        min (pattern.Length - 1) (i + 1)
                    else
                        min (pattern.Length - 1) i

                if pattern[patternIdx] then
                    chars[i] <- Char.ToUpperInvariant chars[i]
                else
                    chars[i] <- Char.ToLowerInvariant chars[i]
            
            // Nếu có phụ âm cuối viết hoa trước phím dấu thanh (ví dụ vIeeTj -> vIệT)
            if len > 0 && pattern.Length >= 2 && pattern[pattern.Length - 2] && not pattern[pattern.Length - 1] then
                chars[len - 1] <- Char.ToUpperInvariant chars[len - 1]
            String chars
```
